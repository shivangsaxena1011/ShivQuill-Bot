**Audit Date:** 2026-11-14  
**Auditor:** Principal Software Engineer & Application Security Specialist  
**Repository:** https://github.com/shivangsaxena1011/ShivQuill-Bot  
**Current Release Branch:** `main` (commit `914df3e`)  
**Target Release Candidate:** v2.2.0

---

## 1. Executive Summary

This independent technical inspection evaluates the ShivQuill v2.1 codebase across backend orchestration, API route security, AI provider handling, frontend user experience, and testing frameworks. While v2.1 established zero-mock enforcement and sequential chunk orchestration, deep source-level inspection identified critical vulnerabilities in job cancellation, corpus management authorization, and client-side security policies, alongside discrepancies in versioning and feature representation.

This document classifies all findings by severity and details the remediation strategy implemented for the v2.2.0 release candidate.

## 3. Detailed Technical Defect Analysis

### 3.1 Defect V22-01: Document Cancellation Failure (CRITICAL)
- **Source Inspection:**
  In `backend/src/llm.ts`:
  ```typescript
  export async function executeLlmCompletion(
    systemPrompt: string,
    userPrompt: string,
    modelOverride?: string,
    temperature = 0.3
  ): Promise<string>
  ```
  The function did not accept `signal?: AbortSignal`.
  In `backend/src/chunkOrchestrator.ts`:
  ```typescript
  const rewritten = await executeLlmCompletion(systemPrompt, userPrompt, this.model);
  ```
  Calling `job.cancel()` aborted `this.abortController`, but:
  1. The underlying HTTP connection with OpenAI/Groq was never aborted.
  2. The chunk loop caught any error in `catch (err: any)`, slept for `attempt * 200ms` without abort listeners, and attempted retries up to 3 times.
  3. When retries failed, the chunk was marked as `partialRecovery` using original text, and the job status was marked as `completed`!
- **Consequence:** Users cancelling a 100-page document continued consuming compute, network bandwidth, and API quota. The job eventually reported success with incomplete or unrewritten text.
- **Fix:**
  - Pass `AbortSignal` through `executeLlmCompletion(..., signal)`.
  - Pass `{ signal }` into `client.chat.completions.create(body, { signal })`.
  - Abort sleep backoffs via `signal.addEventListener('abort')`.
  - Immediately check `signal.aborted` upon error; do not retry aborted jobs.
  - Set status to `'cancelled'` and reject with `JobCancelledError`.

### 3.2 Defect V22-02: Unauthenticated Corpus Poisoning (CRITICAL)
- **Source Inspection:**
  `originalityRouter.post('/corpus', ...)` allowed anonymous callers to ingest arbitrary documents into `defaultCorpusManager`.
- **Consequence:** Any remote actor could inject spam, biased texts, or malicious content into the reference corpus, corrupting plagiarism scores and exhausting server memory.
- **Fix:**
  - Introduce `CORPUS_ADMIN_KEY` environment variable.
  - Add timing-safe middleware comparing `x-admin-key` using `crypto.timingSafeEqual`.
  - If unconfigured or unauthorized, return 401/403.
  - Restrict document size to 50KB, require valid `http:` or `https:` URLs, and enforce duplicate checks.

### 3.3 Defect V22-03: Content Security Policy Disabled (HIGH)
- **Source Inspection:**
  `app.use(helmet({ contentSecurityPolicy: false }))` was used.
- **Consequence:** Disabling CSP completely removes standard browser protections against cross-site scripting and unauthorized content embedding.
- **Fix:** Configure a strict, production-ready Content Security Policy via Helmet while supporting necessary styles and fonts.

### 3.4 Defect V22-04: False "Unlimited Length" Claims (HIGH)
- **Source Inspection:**
  `App.vue` repeatedly stated `(Unlimited Length)` and `(Unlimited)`.
- **Consequence:** Violates truth-in-advertising and technical reality: Express body parser is 10MB and backend Zod schemas enforce a 1,000,000 character maximum.
- **Fix:** Replace all UI occurrences with honest phrasing: `Large Document Support (Up to 1M chars / ~150K words)`.
